Emitter fixes:

- **`.outside` listeners run in the capture phase on every target.** React, Vue, Solid and Lit already dismissed in the capture phase (through their runtime helpers); Angular and Svelte listened in the bubble phase, so the dismissal ran after the consumer's own click handlers. On Angular that undid a handler that repointed a popover at the element just clicked and reopened it, because the dismissal still saw the previous reference. All six targets now dismiss before consumer handlers, see the click target while it is still attached, and ignore a consumer's bubble-phase `stopPropagation` the same way. Angular attaches with `addEventListener(…, true)` (`Renderer2.listen` takes no options) behind a `typeof document` guard for SSR. Components using `.outside` are regenerated (`@rozie-ui/popover` here; the held `@rozie-ui/listbox` in its own entry).
- **Lit event maps include model change events.** A component with an `<emits>` block now lists each `model: true` prop's `<prop>-change` event in its `Rozie<Name>EventMap`, typed `CustomEvent<T>` with the prop's own type, so `addEventListener('open-change', …)` is typed like the declared events.
- **Lit: multi-word props observe their kebab attribute.** A non-model prop such as `idBase` or `matchWidth` now declares `attribute: 'id-base'` / `'match-width'`, the same kebab form model props already used (`page-size`). Before, Lit observed the lowercased name (`idbase`), so a static `id-base="…"` never reached the prop. **Breaking for raw-HTML consumers** who wrote the lowercased or camelCase form (`idbase="…"`, `idBase="…"`, which HTML lowercases): write the kebab attribute (`id-base="…"`) or set the property. Single-word props are unchanged.
- **Static attributes on composed components reach the declared prop on Angular and Lit.** A static `id-base="x"` (or `idBase="x"`) on a Rozie child is now written as the child's input name on Angular (`idBase="x"`; Angular binds a static attribute to an input only under its exact name) and as its kebab attribute on Lit. React, Solid and Svelte already resolved it against the child's declared props, and Vue normalizes it itself.
